Engine at a glance

The engine separates sampled scalar-field generation and meshing from runtime terrain residency. Terrain is generated and baked offline; runtime systems consume precomputed chunk assets.

Using the engine

Create and mesh a point field

PointFieldResource represents a regular sampled scalar field. Cell dimensions describe cells; the sample lattice is one sample larger on every axis. Density values above the iso-level are solid and values below it are empty.

var field := PointFieldResource.new()
field.cell_dimensions = Vector3i(16, 16, 16)
field.sample_spacing = 1.0
field.noise = FastNoiseLite.new()
field.regenerate()

if field.is_data_current():
    var mesh := SurfaceNetsMesher.new().generate_mesh(field, 0.0)

Surface Nets consumes current field data only. Configuration changes may retain packed channels for inspection while marking them stale; stale data is not authoritative meshing input.

Stream precomputed chunks

var streamer := ChunkStreamer.new()
streamer.manifest = preload("res://path/to/terrain_manifest.tres")
streamer.load_radius = 2
streamer.unload_radius = 3
streamer.max_load_starts_per_frame = 2
streamer.max_concurrent_loads = 4
add_child(streamer)
streamer.update_residency(player_position)

ChunkStreamer owns runtime residency and loading. It does not invoke field generation or Surface Nets.

Surface Nets boundary

Topology around crossed sample edges requires neighboring cell context. Chunk or region generation must provide appropriate overlap or halo data when surfaces reach field boundaries; the mesher does not reach into neighboring chunks itself.

Subsystem ownership

PointFieldResource

Authoritative scalar-field representation: geometry, densities, indexing, sampling, validation, serialization, and generation-time field logic.

SurfaceNetsMesher

Consumes a current point field and produces an indexed ArrayMesh.

ChunkAssetBaker

Owns offline chunk asset creation and persistence.

TerrainChunkManifest

Catalogs precomputed chunk assets and spatial metadata.

ChunkStreamer

Owns runtime residency, threaded loading, scheduling, budgets, hysteresis, metrics, and resident scene instances.

Architectural rule: preserve subsystem contracts before optimizing. Change a durable contract only when evidence justifies the cost and the decision is recorded explicitly.

Common library boundary

Project-general Godot capabilities may be promoted into common/ only when their responsibility is genuinely independent of voxel terrain and can be validated independently. Dependency direction is project / demos → voxel terrain engine → common library. NoClipCameraController is the first promoted common capability; terrain-specific field, meshing, asset, manifest, and streaming systems remain voxel-engine responsibilities.

How the project develops

  1. Feature branches: work uses meaningful feature-named branches.
  2. Architecture first: substantial work identifies ownership, contracts, edge cases, and validation before implementation.
  3. Automated proof: deterministic headless tests validate public behavior and architecture guards.
  4. Human-visible proof: substantial engine features have validation scenes using the real public API/runtime path.
  5. Browser proof: relevant validation appears in the long-lived GitHub Pages Integration Preview.
  6. Decision records: durable architecture belongs in ADRs; measurements in performance records; roadmap changes preserve history.

The project treats feature delivery as a chain: production behavior → automated proof → human-visible proof → published browser proof.

Record discipline

Accepted ADRs are superseded rather than rewritten. ROADMAP.md answers what comes next; roadmap history answers why priorities changed; performance reports keep measurement separate from inference. Documentation reports discrepancies instead of inventing architectural resolutions.

Engineering-memory governance

Reusable component promotion

Components move into the common library only when their existing responsibility is independently useful outside terrain, their API is understandable without terrain knowledge, and their validation can stand alone. Extraction must preserve or clarify the public contract rather than broaden responsibilities merely to look generic.
