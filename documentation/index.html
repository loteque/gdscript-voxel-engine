Engine at a glance

The engine separates sampled scalar-field generation and meshing from runtime terrain residency. Terrain is generated and baked offline; runtime systems consume precomputed chunk assets.

Subsystem ownership

PointFieldResource

Authoritative scalar-field representation. Owns sample geometry, densities, indexing, sampling, validation, serialization, and generation-time field logic.

SurfaceNetsMesher

Consumes a point field and produces mesh geometry. It does not own field generation or runtime streaming.

ChunkAssetBaker

Owns offline chunk asset creation and persistence.

TerrainChunkManifest

Catalogs precomputed chunk assets and their spatial metadata.

ChunkStreamer

Owns runtime residency, loading execution, scheduling, and resident scene instances. It does not invoke procedural terrain generation.

Architectural rule: preserve subsystem contracts before optimizing. Performance work should remain behind stable interfaces unless measured evidence justifies a deliberate contract change.

How the project develops

  1. Feature branches: work is performed on branches named for the feature, never generic change branches.
  2. Architecture first: substantial work identifies ownership, contracts, edge cases, and validation before production changes.
  3. Automated proof: deterministic headless tests validate observable behavior and architecture guards.
  4. Human-visible proof: substantial engine features have validation scenes using real public APIs and runtime paths.
  5. Browser proof: relevant validation is exposed through the long-lived GitHub Pages Integration Preview.
  6. Decision records: durable architecture belongs in ADRs; measured evidence in performance records; roadmap changes preserve their history.

The project treats feature delivery as a chain: production behavior → automated proof → human-visible proof → published browser proof.

Current roadmap

The current milestone is resource-loading analysis. Large single-LOD validation identified precomputed resource-loading throughput as the first material scaling pressure visible in current instrumentation. The goal is diagnosis before optimization.

Resource-loading analysis→Loading architecture decision→LOD architecture→Larger volumetric asteroid→Several-kilometer asteroid

Dual Contouring remains planned future meshing work, but is not currently on the critical path to asteroid-scale streaming.
